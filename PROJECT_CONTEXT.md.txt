# Project Vision

## Overview

Industrial Production Monitoring System is a full-stack manufacturing monitoring platform that simulates a modern factory environment.

The system collects production and inspection data from multiple machines, stores the information in SQL Server, and provides operators with a real-time dashboard for monitoring production lines, machines, products, inspections, defects, and production statistics.

Although the project simulates industrial equipment, the architecture is designed exactly like a real production system.

The goal is to demonstrate professional ASP.NET Core backend development using Clean Architecture, Domain-Driven Design principles, Entity Framework Core, SQL Server, SignalR, Angular, testing, Docker, and Azure.

# Finished System

When the project is complete, the system will contain five major components.

A separate .NET application will simulate factory machines.

Each simulated machine will:

- belong to a production line
- produce products

# Current Entity Responsibilities

ProductionLine

- Represents a physical production line.
- Owns a collection of Machines.

Machine

Represents one production machine.

Current behavior:

- Start()
- Stop()
- EnterMaintenance()
- ExitMaintenance()

Status transitions:

Stopped → Running

Running → Stopped

Stopped → Maintenance

Maintenance → Stopped

Cannot:

Maintenance → Running

Running → Maintenance

Machine owns:

- Status
- ProductionLine
- Inspections

---

Product

Represents a product type.

Contains:

- Code
- Name

A Product represents the product definition, NOT produced quantity.

---

Inspection

Represents one inspection event.

Contains:

- Machine
- Product
- Result
- Timestamp
- ProcessingTimeMs

Behavior:

AddDefect()

Business rule:

PASS inspection cannot contain defects.

ProcessingTimeMs cannot be negative.

Defects are exposed as IReadOnlyCollection.

---

Defect

Represents one defect found during inspection.

Contains:

- Type
- Description

Constructor is internal.

Only Inspection creates Defects.

---

# Important Design Decisions

Private setters are used throughout the Domain.

Entities are created through constructors.

EF Core parameterless constructors are private.

Navigation properties use:

= null!

for EF Core compatibility.

Collections use:

ICollection<T>

or

private List<T> + IReadOnlyCollection<T>

where encapsulation is desired.

Entity behavior is preferred over public setters.

Example:

GOOD

machine.Start();

BAD

machine.Status = MachineStatus.Running;

---

# Validation Rules Implemented

ProductionLine

- Name cannot be null
- Name cannot be empty
- Name is trimmed

Machine

- Name cannot be null
- Name cannot be empty
- ProductionLine cannot be null
- Name is trimmed
- Default status = Stopped

Product

- Code required
- Name required
- Both trimmed

Inspection

- Machine required
- Product required
- ProcessingTimeMs >= 0

Defect

- Description required
- Description trimmed

---

# Validation NOT Yet Implemented

Product.Code uniqueness

Reason:

Requires database lookup.

- Application layer
- Database unique constraint

Inspection:

FAIL inspection should contain at least one defect.

Not yet enforced because the current workflow is:

↓

Add Defects

This will be revisited when implementing Application use cases.

# Development Philosophy

This project is intentionally being developed **slowly and incrementally**.

Every architectural decision should be understood before implementation.

Avoid generating the entire application at once.

Each step should include:

- Why we are doing it.
- What problem it solves.
- Alternative approaches.
- Why the chosen approach fits this project.

The goal is to learn professional ASP.NET Core architecture while building a portfolio-quality application.
